# Консультация: фокус поиска при выборе быстрого фильтра на yaclinic.ru/services/

Только рекомендация. Приложение, WordPress, Elementor и опубликованный сайт не меняются. Код страницы /services/ я в этом раунде не читал: обработчик клика по пилюле и способ установки фокуса нужно сначала найти в коде (шаг 0).

## Причина (гипотеза, подтвердить)
Обработчик пилюли записывает текст в поле поиска и вызывает `input.focus()` (или `.select()`), либо ставит фокус через `click()` на поле. На iOS программный фокус внутри жеста пользователя открывает клавиатуру во всех браузерах на WebKit (Chrome, DuckDuckGo, Safari).

## Минимальное решение
1. **Пилюля не фокусирует поле.** Убрать только вызов `focus()/select()/click()` по полю из обработчика пилюли. Текст в поле, активная пилюля, фильтрация, счётчик и URL остаются как сейчас.
2. **Фокус остаётся на нажатой пилюле.** Это кнопка (`<button>`, `aria-pressed="true"`). Мышь и касание: браузер оставляет фокус на кнопке сам. Клавиатура: Enter/Space на пилюле — фокус не уходит, видимое кольцо фокуса сохраняется.
3. **Клавиатура уже открыта, пациент нажал пилюлю.** Нажатие на кнопку само снимает фокус с поля, клавиатура закрывается. Если на каком-то браузере фокус остаётся в поле, в обработчике пилюли вызвать `input.blur()` только когда `document.activeElement === input`. Без задержек и проверок браузера.
4. **Ручной ввод.** Фокус в поле только при касании самого поля. Ввод фильтрует как сейчас. По Enter (`form submit` / `enterkeyhint="search"`) — `preventDefault()` перезагрузки, применить поиск, вызвать `input.blur()`, чтобы клавиатура закрылась и выдача была видна. Пилюли при ручном тексте ведут себя как сейчас (снятие/совпадение) — логику не менять.
5. **Очистка (×).** После очистки фокус оставить в поле: пациент явно хочет вводить заново.
6. **Объявление для скринридера.** Существующий счётчик в `aria-live="polite"`, если ещё не так; новых элементов не добавлять.

## Авто-прокрутка к результатам — не рекомендую по умолчанию
- Если пилюли стоят прямо над выдачей, после закрытия клавиатуры результаты и так видны; прокрутка сдвинет пилюли и ряд фильтров из вида.
- Риски: заголовок первой услуги прячется под закреплённой шапкой; нижние кнопки «Позвонить/Записаться» закрывают последние карточки; на iOS прокрутка во время закрытия клавиатуры прыгает (меняется visualViewport); сбивается восстановление позиции при возврате из услуги; при `prefers-reduced-motion` плавная прокрутка мешает.
- Если по замерам выдача начинается ниже первого экрана — прокручивать только когда верх выдачи вне видимой области, через `scroll-margin-top` на контейнере выдачи = высота шапки + 8px, `behavior: 'auto'` при reduced motion, и только после действия пользователя, не при восстановлении из URL/возврате.

## Критерии приемки
Устройства: iPhone Safari, Chrome iOS, DuckDuckGo iOS; Android Chrome; ПК мышь и клавиатура; ширины 360/390/768/1440.
1. Касание пилюли «выпадение волос»: клавиатура не появляется; поле содержит значение; пилюля активна; счётчик и список совпадают с текущим поведением.
2. Клавиатура открыта → касание пилюли: клавиатура закрывается, применён фильтр пилюли.
3. Касание поля: клавиатура открывается, ввод фильтрует как раньше.
4. Ручной текст + Enter/«Найти»: страница не перезагружается, клавиатура закрывается, результаты видны.
5. Клавиатура ПК: Tab до пилюли, Enter/Space применяет фильтр, фокус и кольцо остаются на пилюле; Tab дальше идёт в выдачу.
6. Порядок услуг, цены, открытие записи, переход в услугу и возврат с восстановлением фильтра и позиции — без изменений.
7. Нет горизонтальной прокрутки; первая карточка не под шапкой; последняя не под нижними кнопками.
8. Режим для слабовидящих и масштаб 200%: поведение то же.
9. Скринридер (VoiceOver): после пилюли объявляется число найденных услуг.

## Риски
- Если фокус ставит сам виджет Elementor или сторонний скрипт, правка должна быть в том же месте, а не поверх через `blur` с таймером.
- `blur()` при каждой пилюле без проверки activeElement сбивает фокус клавиатурных пользователей.
- Кэш страниц/оптимизатор JS может отдавать старый скрипт — проверять после сброса кэша.
- Без реальных тестов на устройствах успех заявлять нельзя; влияние на запись не измерено.
