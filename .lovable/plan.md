# Совет по переносу адресов yaclinic.ru, раунд 1: независимое мнение (только обсуждение)

Ниже — рекомендация одного советника. Это не решение владельца и не проверка клинического содержания. Сайт, редиректы и Метрику агент не проверял. Единственная основа — снимок E1–E9.

Статусы: **301-C** — постоянный 301 после того, как проверено соответствие содержания; **HOLD** — решение ждёт конкретного факта; **OWNER** — решает только владелец; **NO-REDIRECT** — оставить честный 404/410, решение за владельцем.

## Q1. 11 точных совпадений и 81 изменённый адрес
- VERDICT: оставить новые базы /services/, /service/, /advice/, /doctor/. Старые корни не возвращать.
- DECISION: 11 точных совпадений оставить как есть, редирект не нужен. 81 адрес не утверждать пакетом. Проверять построчно: H1/тема, тот же тип страницы (услуга / статья / врач), путь к записи. Каждая строка получает 301-C или переходит в Q2. Исключение «оставить старый путь» допустимо только при доказанной внешней ценности: внешние ссылки, входы из поиска, печатные материалы. Такого доказательства сейчас нет (E7). Значит, исключений по умолчанию нет.
- OBJECTIONS: «высокая посещаемость» по всем источникам (E7) не обосновывает исключение.
- FACTS_NEEDED: старые входы из поиска в Вебмастере и Search Console, внешние ссылки, список печатных и QR-адресов.
- TEST: для каждого из 81 адресов — ровно один переход 301 на конечный адрес с ответом 200. В меню, sitemap и canonical не должно оставаться старых адресов.

## Q2. Несовпадение услуг и содержания
- VERDICT: четыре класса. (A) точный преемник: то же название и метод, отличаются только язык или транслит адреса → 301-C. (B) вероятный преемник, но содержание или метод не подтверждены → HOLD до проверки врачом или редактором. (C) другая услуга → не перенаправлять на неё. Временно показать честный 404 со ссылками на /services/. (D) раздел или категория → вести на каталог /services/ с выбранной категорией, только если такой фильтр технически есть (snippet 17, ucterms/q).
- DECISION: временный вариант для B и C — не придумывать соответствие. До решения строка не реализуется.
- OBJECTIONS: отправить «Интралипотерапию» на «Мезотерапию тела» или «Коллост» на «Коллагенотерапию» — значит выдать одну процедуру за другую.
- FACTS_NEEDED: подтверждение врача по B; есть ли в каталоге параметр категории, сохраняемый в адресе.
- TEST: открыть старый адрес и убедиться, что конечная страница говорит о той же процедуре (H1 и первый блок).

## Q3. Документы, лицензии, отзывы, разделы направлений
- VERDICT: якорь на /patients/ годится, только если там есть полноценный раздел с тем же назначением. Нужен заголовок, само содержимое (сканы лицензий, список документов, отзывы), стабильный id. Иначе — отдельная настоящая страница, но только если содержимое уже существует. Пустых SEO-страниц не создавать.
- DECISION: R112, R113, R115 → HOLD. Сначала сверить состав /patients/. Лицензии и документы по требованиям 118н обычно нужны в легко находимом месте, поэтому отдельная /dokumenty/ — сильный кандидат, если каталог документов переносится. Этот вывод — гипотеза советника. Решает владелец или юрист.
- OBJECTIONS: фрагмент #id не уходит на сервер. Редирект `/licenzii/` → `/patients/#licenzii` задаётся целиком в Location, и браузер его выполнит. Проверка через curl не покажет прокрутку.
- FACTS_NEEDED: какие разделы есть на /patients/; где на новом сайте лицензии.
- TEST: Location содержит нужный #id; в браузере после перехода раздел виден и получает фокус или заголовок; Back возвращает корректно.

## Q4. Черновики сотрудников и дубли Ковалева
- VERDICT: ничего не публиковать и не присваивать роли автоматически.
- DECISION: варианты для каждого человека. (a) работает и согласен на публикацию → владелец утверждает профиль, затем 301-C. (b) не работает или не согласен → черновик не публиковать, старый адрес не перенаправлять на чужой профиль: 404/410 или /doctor/ после решения владельца. (c) неизвестно → HOLD. Администраторы (R86, R87) — немедицинский персонал. Если их публикуют, то не в списке врачей и без медицинской должности. Ковалев: R91 и R130 — два старых адреса. Оба вести 301 на один /doctor/igor-kovalev/, только когда владелец подтвердит, что это один человек и какой текст актуален. Опечатку «Петровичч» не переносить.
- FACTS_NEEDED: текущий штат, согласия на публикацию (ФЗ-152), должности.
- TEST: в /doctor/ нет неутверждённых людей; оба адреса Ковалева приходят в один профиль с ответом 200.

## Q5. 30 непривязанных адресов, архивы, технические
- VERDICT: массовых редиректов на главную нет. Страниц автоматически не создавать.
- DECISION: статьи сначала искать среди 75 статей /advice по заголовку и смыслу. Нашлась → 301-C. Нет → OWNER: перенести текст (с врачебной проверкой) или 404/410. Архивы рубрик: /category/faq/ → /advice/ (301-C). Подрубрики → /advice/ с фильтром, только если фильтр есть, иначе HOLD. «Без рубрики» → 410 по решению владельца. Демо-страницы → 404/410.
- FACTS_NEEDED: старые тексты статей, есть ли у них входы из поиска или внешние ссылки.
- TEST: каждый адрес из списка отдаёт ровно ожидаемый статус. Отдельно проверить: на 404 нет «мягкого 200» с пустой страницей.

## Q6. 198 исторических адресов, правила и параметры
- VERDICT: только список точных адресов. Шаблонов вида `/services/*` и регулярных выражений не использовать. Сравнивать нормализованно: регистр, хвостовой «/», percent-encoding кириллицы.
- DECISION: 198 адресов из Метрики в список не включать. Использовать их как проверочный набор, на котором ловить случайные совпадения. Строку запроса по умолчанию сохранять при 301 (utm, yclid, q). Параметры записи с ID услуги или врача не трогать вообще — эти маршруты в исключения. Якоря #yc-list и #yc-return — клиентские, сервер их не видит.
- OBJECTIONS: правило с подстановкой по `/services/` легко сломает 538 цен на /service/ и snippet 17.
- FACTS_NEEDED: где физически будут правила (плагин, сервер, MU), и как включить или выключить их одним переключателем.
- TEST: таблица «адрес → ожидаемый статус и конечный адрес» на всех 171 + 198 + выборка из новых адресов (все /service/ с параметрами). Rollback: сохранить прежний набор правил и снимок ответов до и после.

## Q7. Метрика
- VERDICT: тот же счётчик и те же цели. Принятой заявкой считать только подтверждённый сервером ответ, не клик и не открытие окна.
- DECISION: разделять тестовый трафик (staging и внутренние IP — фильтр или отдельный счётчик), внутренний и основной. Нужны только четыре вещи: (1) входы на старые адреса после 301 — сколько, по каким строкам; (2) 404 по старым адресам; (3) открытие записи — отдельно от успешной серверной приёмки; (4) приход и оплата — вне Метрики, из SQNS, без смешения с кликами.
- FACTS_NEEDED: какое событие сейчас фиксирует успешную приёмку (по прошлому разбору «успешная отправка» = popup-open).
- TEST: тестовая заявка на staging (только с разрешения владельца) видна только в тестовом сегменте; цель срабатывает один раз.

## Q8. Порядок
1. Только чтение: экспорт правил rewrite/MU/сервера, маршрутов CPT, текущих редиректов и цепочек для 171 адреса.
2. Решения по содержанию: класс A/B/C/D, Q3, Q4, OWNER-строки.
3. Список точных правил (CSV с версией и SHA).
4. Staging: прогон таблицы Q6, проверка Back и записи (E5), мобильная проверка.
5. Релиз: включить правила, обновить sitemap, canonical и внутренние ссылки; снять noindex только на итоговом домене.
6. Первые 14 дней: 404, проверка в Вебмастере и Search Console.

Минимальное доказательство готовности к релизу: зелёная таблица статусов, ноль цепочек длиннее одного шага, в sitemap ноль старых адресов, запись работает на мобильном, rollback проверен.

## Q9. Где подход избыточен
- Не нужно 79 отдельных обсуждений. Около 20 строк класса A подтверждаются за минуты по H1 одним редактором.
- Ловушки: дубли статей (R35/R37, R56/R85, R44/R80, R25/R59, R45/R57) — по одному преемнику на группу. R27: адрес про пигментацию, а заголовок про холодную плазму, сначала выяснить, о чём текст. Кириллические адреса в percent-encoding. Хвостовой «/» и регистр. Старые адреса в печати и QR. Шаблоны writer'а WordPress, автоматически угадывающие адреса (redirect_canonical): проверить, что он не подставляет похожие страницы сам.
- Не забыть 118 «Лазерная шлифовка»: в эталоне такая услуга есть. Возможно, на новом сайте она тоже есть под другим адресом.
