# Прайс: удаление повторов CSS и диагностика ответа сервера

Дата: 21 октября 2026. Объект: `https://new.yaclinic.ru/price/`.

## Результат и границы

На стенде активен сниппет №49. Он сохраняет первую вставку CSS шаблона карточки стоимости Elementor №2913 и пропускает следующие вставки этого же шаблона в одном запросе страницы прайса №2903. Все 218 исходных строк остаются в HTML. Стили других шаблонов не меняются. Сниппет не работает на production, других страницах, в админке, AJAX-запросах, предпросмотре и редакторе.

Production, DNS, сертификаты, настройки PHP/FPM, плагины и исходники Elementor/Unlimited Elements этой оптимизацией не менялись. Исполнители услуг и маршруты записи не менялись. Заявок и обратных звонков не отправлено.

Код: `price-css-once.php`. Регрессионные проверки: `test_price_css.php`. Сводка сравнений: `verification.json`. Проверенные действия пользователя: `ui-checks.json`.

## Подтверждённое уменьшение страницы

Гостевой HTTPS GET, gzip, без авторизации. Первые образцы из серий `before` и `after-final-idle`:

| Показатель | До | После |
|---|---:|---:|
| Копий CSS шаблона №2913 | 218 | 1 |
| HTML после распаковки | 2 383 725 Б | 988 198 Б |
| HTML при передаче, gzip | 169 057 Б | 90 287 Б |
| Встроенный CSS | 1 469 782 Б | 77 510 Б |

| Строк карточек прайса | 218 | 218 |

HTML после распаковки уменьшен на 58,5%, передаваемый HTML — на 46,6%, встроенный CSS — на 94,7%. Это результат для HTML-документа, а не для полного веса всех ресурсов страницы.

Хеш оставленного блока CSS: `dc7673c355cc9e8d61c77143d016a10395b85f6bb75f4c474c225e54eb3bafe1`. Его содержимое не изменилось. Все остальные блоки CSS, ссылки на скрипты и последовательности цен совпали с исходными. На контрольных страницах каталога, биоревитализации и главной CSS, скрипты и цены также совпали с исходными.

## Скорость: без завышения результата

Гостевые серии по три последовательных запроса: медиана TTFB прайса 4,95 → 4,34 с, полная передача HTML 5,49 → 4,64 с. Контрольные страницы тоже показывали колебания. Считать весь этот выигрыш эффектом сниппета нельзя.

**В более поздней финальной серии 12:00–12:02 UTC зафиксирован скачок задержки.** Прайс: 5,25 / 10,66 / 11,69 с, медиана 10,66 с; каталог: медиана 5,97 с; биоревитализация: 3,37 с; главная: 2,93 с. Все 12 запросов вернули HTTP 200, цены/скрипты совпали, прайс по-прежнему не содержал повторного CSS. DNS занимал около 0,003 с, установка TLS — 0,27–0,35 с. Скачок относится к ожиданию ответа после соединения, но конкретная причина очереди/нагрузки в FPM не доказана. Эту серию не скрываем и не заменяем более быстрыми замерами. Задержка сервера остаётся открытым пунктом.

Дополнительно проведено близкое по времени сравнение с выключенным и включённым №49. На время контрольной серии выключался только этот пилот; после серии он снова включён. Условия: Chromium, авторизованная сессия администратора, высота 844 px, DPR 1, CPU ×4, HTTP-кеш выключен, без ограничения сети, по три загрузки для каждой ширины и состояния.

| Метрика, медиана | 390 px, выключен → включён | 1440 px, выключен → включён |
|---|---:|---:|
| TTFB | 3,834 → 4,069 с | 3,942 → 3,888 с |
| Первый показ содержимого, FCP | 5,092 → 5,124 с | 5,148 → 5,172 с |
| Событие полной загрузки | 7,220 → 7,172 с | 8,297 → 7,371 с |

Устойчивое ускорение первого показа и ответа сервера **не доказано**. Основной подтверждённый выигрыш — меньший объём HTML/CSS. Мобильный первый показ остался около 5,1 с. Это лабораторные проверки, не полевые Core Web Vitals, не Lighthouse и не тесты на физических iPhone/Android.

Ранняя серия `after-final-idle` показала более высокие времена; она полностью сохранена в `verification.json`. Поэтому выполнена дополнительная контрольная серия, а не сделан вывод по одному замеру. Неудачный первый пилот и замеры с параллельной диагностикой/дополнительной админской вкладкой не используются как итоговая контрольная пара. Все исходные замеры сохранены локально в `browser.json`.

## Что установлено о серверной задержке

Приватный CLI-профиль загрузки того же WordPress/маршрута, с `SAVEQUERIES` только в диагностическом процессе:

| Показатель | До | После |
|---|---:|---:|
| Полное выполнение | 5 557 мс | 5 567 мс |
| SQL-запросы | 404 | 404 |
| Суммарное время SQL | 205 мс | 210 мс |
| Рендер шаблона №2913, 218 вызовов | 3 015 мс | 3 018 мс |
| Обработчик форматирования цен, 981 вызов | 35,9 мс | 36,4 мс |
| Пиковая память процесса | 158,37 МиБ | 147 МиБ |

Это не профиль PHP-FPM реального HTTP-запроса. Вложенные времена рендера не суммируются с временем родительской страницы. Один профиль не является статистическим доказательством изменения времени или памяти.

Профиль указывает на тяжёлую повторную сборку карточек через Elementor/Unlimited Elements как на основной участок работы прайса. SQL и единый формат цен не объясняют основную часть задержки. Удаление повторного вывода CSS не убирает эти 218 рендеров, поэтому PHP-время почти не изменилось.

Проверены настройки FPM: OPcache включён, память OPcache 128 МБ; пул dynamic с `max_children=5`. В наблюдаемых снимках нагрузка была невысока, доступно около 1 ГБ ОЗУ. Исчерпание воркеров, заполненность рабочего OPcache и точный вклад внешних HTTP-вызовов не установлены. Рабочий FPM slowlog и детальный профиль реального HTTP-запроса в этом этапе не снимались. Увеличивать лимиты и отключать интеграции без этих данных не стали.

В CLI до и после были 440 предупреждений ACF dynamic-tags в Elementor Pro. Они не появились из-за пилота. Код поставщика и подавление предупреждений не менялись.

Следующий технический шаг: ограниченный профиль одного настоящего HTTP-запроса в FPM, затем проверка облегчённого рендера/кеширования неизменной структуры прайса с явной инвалидизацией при изменении цен. Готовый HTML с ценами или записью без такой проверки не кешировать.

## Сохранность данных и проверки

- Перед изменением сделаны приватные снимки сниппетов, каталога и данных двух шаблонов. После обновления другие сниппеты и каталог совпали с состоянием непосредственно перед записью.
- Между первым снимком и обновлением изменились только 538 значений технического поля `sqns_last_synced_at`. Это подтверждено отдельным сравнением. Цены, названия, контент, маршруты и шаблоны не изменились. В сравнении с первым снимком исключено только это поле; оно не перезаписывалось.
- Первый вариант пилота был без эффекта: `is_page()` и текущий документ менялись на услугу внутри Unlimited Elements. Добавлен тест, который сначала воспроизвёл этот сбой, затем прошёл после исправления. Теперь страница фиксируется на хуке `wp`, а ID шаблона берётся из фактического CSS-файла.
- PHP 8.3.6: синтаксис проверен; 26 изолированных проверок прошли. Проверены production/admin/AJAX/preview/editor guards, первый и повторный вывод, другие шаблоны, отсутствие парного события и вложенный вызов.
- На 390 и 1440 px у всех 218 строк совпали текст, данные кнопок записи, вычисленные стили, ширины и высоты. На 360, 768 и 1440 px дополнительно нет горизонтального переполнения и карточек вне ширины страницы.
- Desktop: поиск по названию и сброс, якорь направления, открытие/закрытие формы из строки, общая запись из шапки, переход к онлайн-записи, закрытие Escape.
- Mobile 390 px: раскрытие направлений, переход в раздел, поиск и сброс, запись из строки консультации, выбор врача, календарь, загрузка времени, шаг назад и закрытие.
- Обратный звонок для BioHyalux MEVITA C 4 мл открывается штатно с сообщением о ненастроенной онлайн-записи. Назначение исполнителей оставлено отдельному сервису. Проверки не включали отправку заявки.

## Отдельные находки, не исправлялись в этом этапе

1. Баннер согласия на аналитику перекрывает нижнюю часть окна записи до выбора посетителем. Согласие пользователя ради скриншотов не меняли.
2. При поиске остаются видимыми некоторые дополнения без самостоятельной записи. Поисковый код не менялся; отдельная проверка причины нужна до заявления о полном исправлении поиска.
3. Подзаголовок прайса сообщает «378+ позиций», тогда как исходный HTML содержит 218 строк. Несколько списков имеют существующее ограничение вывода по 10 позиций. Лимиты и содержание в CSS-этапе не менялись.

## Ревью и откат

Ревью по пяти осям: корректность — запрос и шаблон ограничены, первый CSS сохранён; безопасность — нет новых публичных обработчиков и доступа; производительность — уменьшение байтов доказано, ускорение FCP не заявлено; тесты — регрессия и реальные UI-действия проверены; поддержка — два существующих хука, без новых зависимостей и правок поставщика.

Вердикт: **принят узкий этап удаления повторов CSS на стенде**. Это не завершение оптимизации серверного рендера, не приёмка записи в SQNS и не готовность к переключению production.
