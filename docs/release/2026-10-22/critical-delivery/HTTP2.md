# HTTP/2 для основного сайта

Опубликовано 22.10.2026 в 15:28 МСК. В установленном Nginx1.24 есть ngx_http_v2_module. До изменения curl с поддержкой HTTP/2 согласовывал HTTP/1.1. В двух HTTPS server blocks существующего yaclinic-main изменён только listen-параметр:

```diff
-    listen 443 ssl;
+    listen 443 ssl http2;
```

Сохранён исходный vhost вне web root. Сравнение текущего текста перед записью; nginx-t до/после PASS; graceful reload PASS. DNS, сертификаты, глобальный nginx.conf и файлы других vhost не менялись.

После изменения curl согласует HTTP/2, при явном HTTP/1.1 и HTTP/2 основная страница возвращает HTTP200. Все 12 последующих лабораторных загрузок согласовали h2. Bootstrap по обоим протоколам имеет прежний SHA-256. Методы и данные API не менялись.

nginx-t завершился успешно, но выдал **нефатальные protocol options redefined warnings** из-за различий listen options на общем 443 у соседних server blocks. Их не скрывали; соседние конфигурации ради удаления предупреждений не меняли. Это не утверждение об отсутствии любых предупреждений.

HTTP/2 убрал ограничение доставки HTTP/1.1, но сам по себе не обеспечил положительные общие LCP всех страниц: в промежуточной серии были скачки TTFB до8192 мс. Полные отрицательные результаты сохранены локально. После этого отдельно проверено изменение порядка доставки шрифтов, без четырёх агрессивных preload. Итоговые значения — FINAL.md/summary.json.

Синтаксис выбран для установленной1.24: современная директива `http2 on` появилась в1.25.1. Основание: [официальная документация Nginx](https://nginx.org/en/docs/http/ngx_http_v2_module.html).
