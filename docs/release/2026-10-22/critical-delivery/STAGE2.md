# Убрана последовательная загрузка первого открытия

Опубликовано 22.10.2026 в 15:13 МСК. Пользовательский intent запускает public bootstrap GET одновременно с загрузкой JavaScript. Виджет один раз использует общий Promise; при ошибке сохраняет обычный GET и штатное сообщение об ошибке. До intent нет нового GET или bundle download, доступность и персональные ответы не кешируются.

Производный bundle отличается от предыдущего ровно двумя преобразованиями: адаптер fb() и замена общего Google Fonts URL на локальный CSS тех же шрифтов. Остальной код побайтно совпадает при обратном преобразовании. Оригиналы плагинов не менялись. Loader добавляет только запуск общего запроса перед созданием script; сохранены контекст, повторные нажатия, retry и восстановление фокуса.

Независимая регрессия: исходник 4 FAIL /4 PASS, кандидат 8/8 PASS. Прежние 9 сценариев loader PASS. PHP/head configuration 9 проверок без failures, JS syntax PASS. До публикации расширенный head-тест обнаружил пропущенные переменные замыкания в промежуточном кандидате; они исправлены до публикации.

Шесть холодных открытий в отдельных браузерных контекстах: до выбора услуг mobile медиана2683 →1671 мс; desktop1548 →731 мс. На каждом проходе по одному bootstrap GET и bundle download, запросы стартуют параллельно, до intent bundle отсутствует. Закрытие работает, JS errors и write requests отсутствуют. Это не реальная доставка записи.

Промежуточная серия страниц сохранена полностью: desktop LCP улучшился, mobile ухудшился после ранних preload на HTTP/1.1. Поэтому общий скоростной GO на этом этапе не выдан; отрицательные результаты не удалены. Дополнительно подтверждено отсутствие HTTP/2 в main vhost при наличии поддерживающего модуля. Следующая отдельная правка — два listen-параметра с точным backup, nginx-t, graceful reload и новой after-серией. DNS/сертификаты/глобальные параметры и прочие vhost не менять.
