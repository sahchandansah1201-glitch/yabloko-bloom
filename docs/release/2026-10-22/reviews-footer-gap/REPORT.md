# Пустота между отзывами и подвалом — исправление стенда

Дата: 2026-10-22, Europe/Moscow. URL: https://new.yaclinic.ru/.
Статус: опубликовано и проверено гостем. Production и DNS не изменялись.

## Причина и минимальная правка

На мобильной ширине внешний Elementor flex-контейнер отзывов сохранял избыточную высоту после динамической отрисовки reviews-widget. Например, после загрузки страницы на 390 px высота видимого виджета была 2015.984375 px, а обёртки — 3325.578125 px; до подвала оставалось 1309.59375 px. При переключении источников разрыв также сохранялся.

Проба одного свойства display:block у внутреннего контейнера устранила разрыв; при отмене пробы он вернулся. Пробы min-height:0 у обёртки и height:auto у внутреннего контейнера не помогли и не вошли в публикацию. Конкретный внутренний механизм кеширования размеров браузером не утверждается как доказанный.

В существующий snippet 31 добавлено ровно одно правило:

```css
@media(max-width:767px){
  body.page-id-6 .elementor-6 .elementor-element-48f6d12>.e-con-inner{
    display:block;
  }
}
```

Действует только на мобильной ширине главной страницы стенда. Оригинальные hostname/front-page/page-ID guards сохранены. Отрицательных отступов, фиксированной высоты, обрезки содержимого и новых плагинов нет. Нативные панели отзывов и их обработчики не менялись.

## До и после

Гостевой Chromium, ширина 390 px, расстояние от нижней границы reviews-widget до начала footer:

| Яндекс | 1309.59375 | 0 |

Штатный внутренний нижний отступ самого блока отзывов сохранён. На 1440 px прежний внешний отступ 10 px не изменился.

## Проверка

- Регрессионный порог 80 px до исправления дал ожидаемую ошибку: footer gap 1229.59375 px в первом воспроизведении.
- Сохранённая матрица до исправления также не проходит assert-results.cjs: 360 px, Яндекс, 1289.59375 px.
- После публикации: 4 источника × 360/390/768/1440 px — 16/16 состояний PASS. Нет горизонтального переполнения; подвал виден.
- Хеши текста каждой панели, число ссылок и нативный класс панели совпали с исходной матрицей при той же ширине. Это контроль сохранности, а не аудит достоверности отзывов.
- На 767 px применяется display:block; на 768 и 1440 px остаётся display:flex. Разрыв не возникает.
- Раскрытие длинного отзыва увеличило высоту с 2015.984375 до 2095.984375 px, ответа клиники — до 2383.984375 px. Разрыв до подвала в обоих случаях 0.
- Мобильная закреплённая кнопка «Записаться» загрузила «Запись на приём», шаг 1 из 5, все пять групп услуг; закрытие работает. Никакие данные пациента не вводились, заявка не отправлялась.
- Кнопка настроек cookie осталась в подвале.
- Исходник экспортирован до изменения. После сохранения редактор перезагружен и код экспортирован повторно: нормализованный код точно совпал с ожидаемым.
- Публичный GET главной без cookies: 200, одно вхождение style yc-home-review-width с новым правилом.
- Публичные GET страницы услуги биоревитализации и профиля Марии Павлюк: 200, изменяемый style на них отсутствует.
- node --check browser-regression.js: PASS. assert-results.cjs на after-browser.json: PASS.
- PHP CLI lint не запускался. Изменена только CSS-строка; WordPress сохранил активный snippet и публично вывел ожидаемый style.

## Артефакты

- snippet-31-before.php — исходник для отката, экспорт через штатный редактор.
- snippet-31-after.php — ожидаемый код; snippet-31-readback.php — повторный экспорт.
- before-browser.json / after-browser.json — отдельные замеры до/после.
- extra-browser.json — границы breakpoint, раскрытия и запись.
- browser-regression.js — повторяемый сценарий Playwright CLI; возвращает измерения, не меняет сервер.
- assert-results.cjs — сравнение сохранённых результатов и точности source/readback.
- after-mobile-390.png / after-desktop-1440.png — скриншоты публичного результата.

Команды для проверки сохранённых результатов:
```sh
node assert-results.cjs before-browser.json # ожидаемая ошибка на исходном дефекте
node assert-results.cjs # PASS после исправления
```

## Ограничения и откат

Мобильная проверка сделана в реальном Chromium с заданным viewport, не на физическом iPhone/Android. Во время замеров сохранились два ранее наблюдавшихся сообщения консоли из jquery-core-js-after / MutationObserver и HTTP Elementor custom-lightbox stylesheet; эта CSS-правка их не изменяет.

Для отката удалить только добавленный media-rule из snippet 31 либо восстановить точный snippet-31-before.php через редактор, без служебной шапки экспорта. Не отключать весь snippet: это вернуло бы старую структуру отзывов. Базу данных, тексты отзывов и записи пациентов восстанавливать не нужно.
